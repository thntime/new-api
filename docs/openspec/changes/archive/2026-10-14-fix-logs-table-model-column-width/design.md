## 现状与根因

使用日志表未开启 `enableColumnResizing`，`data-table-colgroup.tsx` 按各列 `size` 占比分配宽度（`size / totalSize * 100%`）。因此任一新列的 `size` 都会等比压缩其它列。

- 加「重试次数」列之前，管理员（common）视图总 size = 1570，模型列 150 占比 9.554%。
- 新增列未设 `size`（默认 150）→ 总 size 1720；`5a9fddace` 收到 80 → 总 size 1650，模型列占比 9.091%，仍低于加列前。
- 模型列 cell 内 `ModelBadge` 的 Button 使用 `flex-wrap justify-start`，徽标 `max-w-full` 在模型名较长时会占满可用宽度，尾部 `shrink-0` 的小图标只能换行到第二行。

## 修复方案

把「重试次数」列占用的 80 从其余三列中收回，使总 size 回到 1570：

| 列 | 原 size | 新 size | 理由 |
| --- | --- | --- | --- |
| channel | 150（默认） | 130 | cell 内层已限制 `max-w-[160px]`，主内容是短渠道号徽标，可安全收窄 |
| user | 150（默认） | 120 | 用户名为 `truncate` 且有 tooltip 承载完整值 |
| token_name | 160 | 130 | 令牌名为 `truncate`，单元格本身可变宽 |

「重试次数」列保持 80：cell 只显示个位数或 `-`，无进一步压缩空间。

总 size 核算：180 + 130 + 80 + 120 + 130 + 150 + 150 + 150 + 150 + 150 + 180 = 1570（与加列前一致）。

## 验证方式

- 回归测试：断言「渠道 + 用户 + 令牌」三列宽度之和等于加列前 460 减去「重试次数」列宽；实现前该用例必须失败（RED）。
- 手工核对：管理员使用日志列表中模型名较长的行，模型徽标与尾部小图标处于同一行；非管理员视图不受影响。
