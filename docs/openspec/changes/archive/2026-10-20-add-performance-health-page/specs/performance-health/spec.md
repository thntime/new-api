# Spec Delta

## Purpose

为管理员提供基于请求日志的性能与可用性聚合视图，支持按时间、模型、渠道、分组与令牌等维度筛选，并展示 TPS、延迟、成功率、可用率趋势与维度分解结果。

## ADDED Requirements

### Requirement: 菜单入口与访问控制

系统 MUST 在侧边栏「使用日志」「审计日志」之后提供「性能健康」菜单，且该菜单与页面 MUST 仅对管理员可见和可访问。

#### Scenario: 管理员看到菜单

- **WHEN** 管理员登录并展开侧边栏
- **THEN** 在「审计日志」之后显示「性能健康」菜单项

#### Scenario: 非管理员看不到菜单

- **WHEN** 非管理员用户登录
- **THEN** 侧边栏不显示「性能健康」菜单

#### Scenario: 非管理员直接访问路由

- **WHEN** 非管理员直接访问 `/usage-logs/performance`
- **THEN** 页面拒绝访问并给出无权限提示，不展示任何性能数据

### Requirement: 筛选条件

页面 MUST 提供时间范围、时间粒度、模型、渠道、分组、令牌（API Key）、用户、是否流式八类筛选条件，且筛选值 MUST 同时作用于页面全部展示区块。令牌筛选 MUST 按令牌名称精确匹配。

#### Scenario: 按维度筛选

- **WHEN** 管理员选择模型 `gpt-4o`、渠道 `#12`、分组 `vip` 并提交
- **THEN** 概览、趋势、维度分解与异常列表均只统计满足全部条件的日志

#### Scenario: 清空筛选

- **WHEN** 管理员清空已选的模型、渠道、分组、令牌与用户
- **THEN** 页面恢复为仅按时间范围统计

### Requirement: 默认时间范围与时间粒度

页面 MUST 默认展示最近 24 小时数据，并 MUST 根据所选时间范围自动选择时间粒度。粒度取值 MUST 限定为 1 分钟、5 分钟、15 分钟、1 小时、1 天，且趋势数据点数量 MUST NOT 超过 120 个。

#### Scenario: 首次打开

- **WHEN** 管理员首次打开页面且未设置筛选
- **THEN** 展示最近 24 小时、按小时聚合的数据

#### Scenario: 选择超长时间范围

- **WHEN** 管理员选择 30 天时间范围
- **THEN** 时间粒度自动调整为天级，趋势图数据点数量不超过页面上限

### Requirement: 请求量与成功率口径

系统 MUST 以消费日志条数作为成功请求数、以错误日志条数作为失败请求数，成功率 MUST 等于成功请求数除以成功与失败请求数之和；分母为零时 MUST 返回空值而非 0%。

#### Scenario: 存在成功与失败请求

- **WHEN** 时间范围内有 90 条消费日志与 10 条错误日志
- **THEN** 请求总数为 100，成功率为 90%

#### Scenario: 无任何请求

- **WHEN** 时间范围内没有任何消费或错误日志
- **THEN** 成功率显示为空占位，不显示 0%

### Requirement: TPS 指标口径

系统 MUST 以单次请求的输出 token 数除以该请求耗时（秒）作为该请求 TPS，并在每个时间桶与整体统计中给出平均值、最大值与最小值；耗时小于等于 0 或输出 token 为 0 的请求 MUST NOT 计入 TPS 统计。

#### Scenario: 计算单请求 TPS

- **WHEN** 某请求输出 200 个 token、耗时 4 秒
- **THEN** 该请求 TPS 为 50

#### Scenario: 耗时为 0 的请求

- **WHEN** 某请求耗时记录为 0 秒
- **THEN** 该请求不计入平均、最大与最小 TPS

#### Scenario: 时间桶内聚合

- **WHEN** 某时间桶内请求 TPS 分别为 10、30、50
- **THEN** 该桶平均 TPS 为 30，最大为 50，最小为 10

### Requirement: 延迟指标口径

系统 MUST 以请求耗时（秒）作为延迟，并 MUST 展示平均延迟与 P95 延迟。P95 MUST 按耗时升序定位第 95 百分位；为控制查询规模，超过 600 秒的耗时 MUST 先按 600 秒归并再定位。

#### Scenario: 平均延迟

- **WHEN** 时间范围内各请求耗时为 1、2、3 秒
- **THEN** 平均延迟为 2 秒

#### Scenario: P95 延迟

- **WHEN** 时间范围内存在 100 条耗时记录
- **THEN** P95 延迟取升序排列后第 95 条记录的耗时

### Requirement: Token 指标口径

系统 MUST 分别汇总输入 token、输出 token 与总 token，并 MUST 在趋势与维度分解中保持同一口径。

#### Scenario: 汇总 token

- **WHEN** 时间范围内输入 token 合计 1000、输出 token 合计 2000
- **THEN** 总 token 显示为 3000

### Requirement: 概览指标卡

页面 MUST 在顶部展示请求总数、成功率、错误数、平均 TPS、最大 TPS、最小 TPS、平均延迟、P95 延迟、输入 token、输出 token 与总 token。

#### Scenario: 有数据时展示

- **WHEN** 筛选结果包含请求
- **THEN** 每个指标卡展示对应数值并按各自单位格式化

#### Scenario: 指标无数据

- **WHEN** 某项指标因分母为零或数据缺失无法计算
- **THEN** 该指标卡显示空占位并保持布局稳定

### Requirement: 趋势图

页面 MUST 展示 TPS 趋势（平均、最大、最小）、延迟趋势（平均、P95）、可用率趋势（成功率与失败数）以及请求量与 token 趋势。

#### Scenario: TPS 趋势

- **WHEN** 管理员查看 TPS 趋势图
- **THEN** 图中同时包含平均、最大、最小 TPS 三条序列，且按所选时间粒度分桶

#### Scenario: 可用率趋势

- **WHEN** 管理员查看可用率趋势图
- **THEN** 图中展示各时间桶的成功率百分比，并同时展示失败请求数

### Requirement: 维度分解表

页面 MUST 提供按分组、模型、渠道三个维度的性能分解表，每个维度 MUST 展示请求数、成功率、平均延迟、平均 TPS、最大 TPS、最小 TPS 与总 token。

#### Scenario: 分组分解

- **WHEN** 管理员查看分组性能表
- **THEN** 每个分组各占一行，并展示该分组的完整指标

#### Scenario: 按请求数排序

- **WHEN** 维度分解表加载完成
- **THEN** 默认按请求数降序排列，管理员可切换排序字段

### Requirement: 异常定位列表

页面 MUST 展示耗时最长的请求 Top N 与错误日志 Top N，并 MUST 提供跳转到对应使用日志详情的入口。

#### Scenario: 最慢请求

- **WHEN** 管理员查看最慢请求列表
- **THEN** 列表按耗时降序展示请求时间、模型、渠道、令牌、耗时与输出 token

#### Scenario: 错误日志

- **WHEN** 管理员查看错误日志列表
- **THEN** 列表按时间降序展示错误请求的时间、模型、渠道、令牌与错误摘要

### Requirement: 展示一致性与加载状态

同一次查询产生的全部区块 MUST 使用同一份筛选快照；加载中 MUST 显示骨架或加载态，单个区块失败 MUST NOT 清空其他已成功区块。

#### Scenario: 切换筛选

- **WHEN** 管理员修改任一筛选条件并提交
- **THEN** 全部区块基于同一组筛选参数刷新

#### Scenario: 区块请求失败

- **WHEN** 聚合请求返回错误
- **THEN** 页面显示错误提示与重试入口，并保留筛选条件

### Requirement: 聚合范围上限

系统 MUST 对聚合查询的时间跨度与数据点数量设置上限，超过上限时 MUST 拒绝请求并返回明确错误信息。

#### Scenario: 超过最大时间跨度

- **WHEN** 请求的时间跨度超过允许上限
- **THEN** 接口返回参数错误，页面提示调整时间范围

#### Scenario: 数据点过多

- **WHEN** 请求的时间粒度会产生超过上限的数据点
- **THEN** 接口返回参数错误或自动合并粒度，页面展示实际采用的粒度

### Requirement: 多数据库兼容

聚合查询 MUST 在 SQLite、MySQL、PostgreSQL 与 ClickHouse 日志库下返回一致语义的结果，且 MUST NOT 依赖任何单一数据库的专有函数。

#### Scenario: ClickHouse 日志库

- **WHEN** 日志库配置为 ClickHouse
- **THEN** 页面全部指标正常返回且不出现 SQL 错误

#### Scenario: 主库为 PostgreSQL

- **WHEN** 日志库为主库 PostgreSQL
- **THEN** 分组等保留字列名查询正常执行

### Requirement: 接口权限与路由声明

新增聚合接口 MUST 要求管理员权限，并 MUST 在访问令牌路由声明中登记对应作用域。

#### Scenario: 普通用户调用接口

- **WHEN** 普通用户调用性能聚合接口
- **THEN** 返回 403，不返回任何统计数据

#### Scenario: 访问令牌调用接口

- **WHEN** 具备日志读取作用域的访问令牌调用该接口
- **THEN** 请求通过路由声明校验并返回数据
