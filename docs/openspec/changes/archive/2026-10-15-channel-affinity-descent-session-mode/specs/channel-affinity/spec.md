# Spec Delta

## Purpose

定义渠道亲和性的会话行为契约：会话如何绑定并复用上次成功使用的原渠道、原渠道失败后如何在候选池中继续选择渠道，以及各会话模式对重试推进方式的约定。

## ADDED Requirements

### Requirement: descent 会话模式复用原渠道

当渠道亲和性命中某渠道时，`descent` 会话模式 MUST 在首次尝试（retry=0）直接使用该原渠道，不触发额外的候选池选择。

#### Scenario: 亲和命中后首轮使用原渠道

- **WHEN** 会话亲和性命中渠道 X，且 X 不是候选池中最高优先级的渠道
- **THEN** 首次尝试使用渠道 X，不按优先级重新选择渠道

#### Scenario: 亲和命中且请求成功

- **WHEN** 会话亲和性命中渠道 X，且 X 处理请求成功
- **THEN** 不进入重试，不发生任何层间移动

### Requirement: descent 会话模式按优先级层环形下降

`descent` 会话模式在重试时 MUST 以原渠道所在的优先级层为起点、按优先级从高到低的顺序逐层向下推进，每重试一次下降一层；到达最低优先级层后 MUST 回绕到最高优先级层继续下降，形成闭环。该推进 MUST NOT 跳回最高层后重新开始常规降序。

#### Scenario: 原渠道失败后逐层向下并回绕

- **WHEN** 候选池包含 50 个优先级层（优先级 60 最高、11 最低），原渠道位于优先级 57 的层，且原渠道返回可重试错误（例如 429）
- **THEN** 后续尝试的层序依次为优先级 56、55、…、11，随后回绕为 60、59、58，再回到 57

#### Scenario: 同一层内保持按权重随机

- **WHEN** 某个优先级层包含多台渠道
- **THEN** 该层内仍按渠道权重加权随机选择，不固定为其中某一台

#### Scenario: 环形回到原层时不排除本轮已失败渠道

- **WHEN** 重试次数足以走完一整环并回到原渠道所在的优先级层
- **THEN** 该层仍参与选择，不因本轮已被尝试过而被排除

#### Scenario: auto 分组跨组后环序重新开始

- **WHEN** 使用 auto 分组且当前分组内没有可用渠道，系统切换到下一个分组
- **THEN** 在新分组内从该分组最高优先级层重新开始，不继承上一分组的环形位置

### Requirement: descent 会话模式无亲和命中时的环序

当会话亲和性未命中（无缓存、缓存过期或规则不匹配）时，`descent` 会话模式 MUST 从候选池最高优先级层开始首次尝试；此时环形顺序 MUST 与常规优先级降序一致。

#### Scenario: 无亲和命中时首轮为最高层

- **WHEN** 会话亲和性未命中且会话模式为 `descent`
- **THEN** 首次尝试使用候选池最高优先级层的渠道

#### Scenario: 无亲和命中时的后续重试顺序

- **WHEN** 会话亲和性未命中，最高优先级层的渠道失败并进入重试
- **THEN** 后续尝试按优先级降序逐层向下推进，与常规优先级选择顺序逐位一致

### Requirement: descent 会话模式的配置接受范围

全局渠道亲和性默认会话模式与规则级会话模式 MUST 同时接受 `descent` 取值。无法识别的会话模式取值 MUST 仍被拒绝，MUST NOT 被静默降级为其它取值。

#### Scenario: 全局默认选择 descent

- **WHEN** 管理员将全局默认会话模式设置为 `descent` 并保存
- **THEN** 配置校验通过并生效，未显式覆盖该值的规则继承该默认

#### Scenario: 规则级选择 descent

- **WHEN** 管理员为某条会话规则设置会话模式 `descent` 并保存
- **THEN** 配置校验通过，匹配该规则的请求按 `descent` 语义选择渠道

#### Scenario: 未知取值仍被拒绝

- **WHEN** 配置中出现不属于 `off` / `prefer` / `strict` / `descent`（规则级另含 `inherit`）的会话模式取值
- **THEN** 配置校验失败并被明确拒绝，而不是静默回退到默认模式

### Requirement: descent 会话模式不影响其它会话模式

新增 `descent` 取值 MUST NOT 改变 `inherit` / `off` / `prefer` / `strict` 的既有行为，也 MUST NOT 改变渠道 pin 所定义的单次尝试与同渠道重试语义。

#### Scenario: prefer 模式行为不变

- **WHEN** 会话模式为 `prefer` 且亲和命中的渠道失败进入重试
- **THEN** 重试仍按常规优先级从最高层重新选择，不使用环形下降顺序

#### Scenario: strict 模式行为不变

- **WHEN** 会话模式为 `strict` 且亲和命中的渠道失败
- **THEN** 请求仍直接终止，不进入重试

#### Scenario: 渠道 pin 语义不变

- **WHEN** 请求被渠道 pin 约束为单次尝试
- **THEN** 失败后仍不重试，与 `descent` 无关
