## Purpose

定义使用日志列表的列展示行为，使管理员能够在列表上直接看到每次请求在渠道链路中的重试次数，用于快速识别频繁重试的请求与渠道。

## ADDED Requirements

### Requirement: 链路次数列的可见性与位置

使用日志（common 类）列表 MUST 在「渠道」列之后新增「链路次数」列，且该列 MUST 仅对管理员可见。非管理员视角 MUST NOT 渲染该列。

#### Scenario: 管理员查看使用日志

- **WHEN** 管理员打开使用日志（common 类）列表
- **THEN** 在「渠道」列之后显示「链路次数」列

#### Scenario: 非管理员查看使用日志

- **WHEN** 非管理员用户打开使用日志（common 类）列表
- **THEN** 不渲染「链路次数」列

### Requirement: 链路次数取值

「链路次数」列 MUST 展示本次请求在渠道链路中除首次尝试之外的重试次数。取值 MUST 基于该日志已记录的渠道尝试序列，重试次数等于尝试序列长度减一。

#### Scenario: 未发生重试

- **WHEN** 某条日志记录的渠道尝试序列只有一次尝试
- **THEN** 「链路次数」列显示 `0`

#### Scenario: 发生多次重试

- **WHEN** 某条日志记录的渠道尝试序列包含 3 次尝试（1 次首次 + 2 次重试）
- **THEN** 「链路次数」列显示 `2`

### Requirement: 无渠道链路时的空值处理

对于不经过上游渠道链路的日志类型（如登录、充值、系统类），或渠道尝试序列缺失的日志，该列 MUST 显示为空占位，且 MUST NOT 显示为 `0`。

#### Scenario: 非 relay 类日志

- **WHEN** 某条日志记录不属于可展示的 relay 类日志（例如登录或充值日志）
- **THEN** 「链路次数」列不渲染内容（与「渠道」列一致），且不显示 `0`

#### Scenario: 渠道尝试序列缺失

- **WHEN** 某条 relay 日志缺少渠道尝试序列数据
- **THEN** 「链路次数」列显示空占位，且不产生运行时错误
