# Spec Delta

## ADDED Requirements

### Requirement: 兜底渠道池配置

系统 MUST 提供一份全局兜底渠道池配置，内容为一组渠道 ID。兜底渠道 MUST NOT 参与正常候选池的优先级层选择；未配置兜底渠道池时，请求的渠道选择行为 MUST 与既有实现一致。

#### Scenario: 保存兜底渠道池

- **WHEN** 管理员在渠道亲和 / 请求策略设置中填写一组渠道 ID 并保存
- **THEN** 配置校验通过并生效，后续请求在正常候选耗尽时使用该列表

#### Scenario: 未配置兜底渠道池

- **WHEN** 兜底渠道池为空
- **THEN** 请求在正常候选耗尽后按既有语义结束（含 `descent` 的环形回绕），不进入兜底阶段

#### Scenario: 兜底渠道退出正常候选池

- **WHEN** 某渠道被列入兜底渠道池，且它在候选池中同时满足分组、模型与请求约束
- **THEN** 该渠道不再作为正常优先级层的候选，只在兜底阶段被选中

#### Scenario: 兜底渠道不满足本次请求约束

- **WHEN** 兜底渠道池中的某渠道不存在、分组或模型不匹配，或不满足本次请求的渠道约束
- **THEN** 该渠道被跳过，其余兜底渠道继续参与兜底阶段，不因此报错

### Requirement: 正常候选耗尽后进入兜底阶段

当一次请求的正常候选优先级层全部失败（含重试预算用尽与环形回绕后的失败）时，系统 MUST 无条件追加兜底阶段继续尝试兜底渠道池。兜底阶段的尝试 MUST NOT 计入重试次数预算，也 MUST NOT 因预算耗尽被截断。

#### Scenario: 正常层用满预算后追加兜底

- **WHEN** 候选池优先级层为 10 / 20 / 30 / 40 / 50（50 最高），重试次数为 5，兜底渠道池为渠道 66（优先级 6）与渠道 55（优先级 5），且所有尝试均失败
- **THEN** 尝试顺序为 50、40、30、20、10、50（回绕）、66、55

#### Scenario: 正常层任一渠道成功

- **WHEN** 正常候选优先级层中的某个渠道处理请求成功
- **THEN** 不进入兜底阶段，兜底渠道不被尝试

#### Scenario: 兜底阶段全部失败

- **WHEN** 兜底渠道池中的渠道全部尝试失败
- **THEN** 请求返回失败，错误语义与既有重试耗尽后的失败一致

#### Scenario: auto 分组下所有分组跑完后只执行一次兜底

- **WHEN** 令牌分组为 `auto` 且解析出多个分组，各分组按既有语义跑完后仍全部失败
- **THEN** 兜底阶段在所有分组跑完后只执行一次，按进入兜底阶段时的当前分组过滤兜底渠道；单个分组的重试预算耗尽不单独触发兜底阶段

### Requirement: 兜底阶段内的层序与层内选择

兜底阶段 MUST 按兜底渠道自身的优先级从高到低逐层推进，每层尝试一次；同一优先级层内包含多台兜底渠道时 MUST 按渠道权重加权随机选择，MUST NOT 固定为其中某一台。

#### Scenario: 按兜底渠道自身优先级降序推进

- **WHEN** 兜底渠道池包含优先级 6 与优先级 5 两个层
- **THEN** 先尝试优先级 6 的层，该层失败后再尝试优先级 5 的层

#### Scenario: 同层多台兜底渠道按权重随机

- **WHEN** 同一兜底优先级层包含多台渠道
- **THEN** 该层内按渠道权重加权随机选择，不固定为其中某一台

### Requirement: 正常候选池为空时进入兜底阶段

当正常候选池为空（分组、模型或请求约束导致无可用候选，或会话模式使正常候选不可用）时，系统 MUST 先尝试兜底渠道池，而不是直接返回无可用渠道。当兜底渠道池为空、或没有任何兜底渠道满足本次请求约束时，系统 MUST 保持既有失败语义，并记录一条 `fallback_exhausted` 决策事件，以便与「未配置兜底渠道池」区分。

#### Scenario: 候选池为空但有兜底渠道

- **WHEN** 本次请求在正常候选池中没有任何可用渠道，且兜底渠道池中存在满足约束的渠道
- **THEN** 请求使用兜底渠道，不返回无可用渠道错误

#### Scenario: 候选池为空且无兜底渠道

- **WHEN** 本次请求在正常候选池中没有任何可用渠道，且兜底渠道池为空或全部被跳过
- **THEN** 请求返回无可用渠道错误，与既有语义一致，并记录一条 `fallback_exhausted` 决策事件

### Requirement: 兜底渠道不参与渠道亲和缓存

兜底渠道 MUST NOT 写入渠道亲和缓存，MUST NOT 更新会话绑定，也 MUST NOT 成为 `descent` 会话模式的环形锚点。

#### Scenario: 兜底渠道成功不写入亲和缓存

- **WHEN** 请求由兜底渠道处理成功
- **THEN** 渠道亲和缓存不更新，后续请求仍按原有亲和命中结果或原有锚点选择渠道

#### Scenario: descent 模式下兜底渠道成功

- **WHEN** 会话模式为 `descent`，正常候选耗尽后由兜底渠道处理成功
- **THEN** 环形锚点保持不变，后续请求的层序起点不受该兜底渠道影响

## MODIFIED Requirements

### Requirement: descent 会话模式不影响其它会话模式

`descent` 取值 MUST NOT 改变 `inherit` / `off` / `prefer` / `strict` 在正常候选池内的既有选择与重试语义，也 MUST NOT 改变渠道 pin 所定义的单次尝试与同渠道重试语义。兜底阶段的启用范围由独立需求约定。

#### Scenario: prefer 模式行为不变

- **WHEN** 会话模式为 `prefer` 且亲和命中的渠道失败进入重试
- **THEN** 重试仍按常规优先级从最高层重新选择，不使用环形下降顺序

#### Scenario: strict 模式行为不变

- **WHEN** 会话模式为 `strict` 且亲和命中的渠道失败，或亲和不可用
- **THEN** 仍不重试正常候选池中的其它渠道；存在满足本次请求约束的兜底渠道时进入兜底阶段，不存在时仍直接终止

#### Scenario: 渠道 pin 语义不变

- **WHEN** 请求被渠道 pin 约束为单次尝试
- **THEN** 失败后仍不重试，也不进入兜底阶段，与 `descent` 无关
