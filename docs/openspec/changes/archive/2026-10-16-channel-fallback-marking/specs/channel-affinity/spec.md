# Spec Delta

## MODIFIED Requirements

### Requirement: 兜底渠道池配置

系统 MUST 让「是否兜底」成为渠道自身的属性：每个渠道带一个可配置的兜底标记，被标记的渠道构成兜底渠道池，且 MUST NOT 参与正常候选池的优先级层选择。系统 MUST 同时提供一个全局兜底功能总开关；总开关关闭时，兜底功能整体不生效。

#### Scenario: 保存兜底渠道池

- **WHEN** 管理员在渠道新增或编辑中开启某渠道的兜底标记并保存
- **THEN** 配置校验通过并生效，该渠道在后续请求的正常候选耗尽时作为兜底渠道参与选择

#### Scenario: 在渠道列表内切换兜底标记

- **WHEN** 管理员在渠道列表的兜底列点击切换某渠道的兜底标记
- **THEN** 该渠道立即加入或移出兜底渠道池，后续请求按新状态选择渠道

#### Scenario: 未配置兜底渠道池

- **WHEN** 没有任何渠道被标记为兜底，或兜底功能总开关关闭
- **THEN** 请求在正常候选耗尽后按既有语义结束（含 `descent` 的环形回绕），不进入兜底阶段

#### Scenario: 总开关关闭时已标记的渠道不参与兜底

- **WHEN** 存在被标记为兜底的渠道，但管理员关闭了兜底功能总开关
- **THEN** 请求不进入兜底阶段，行为与没有任何渠道被标记时一致（含 `strict` 与正常候选池为空的路径）

#### Scenario: 兜底渠道退出正常候选池

- **WHEN** 某渠道被标记为兜底，且它在候选池中同时满足分组、模型与请求约束
- **THEN** 该渠道不再作为正常优先级层的候选，只在兜底阶段被选中

#### Scenario: 兜底渠道不满足本次请求约束

- **WHEN** 被标记为兜底的某渠道不存在、分组或模型不匹配，或不满足本次请求的渠道约束
- **THEN** 该渠道被跳过，其余兜底渠道继续参与兜底阶段，不因此报错

### Requirement: 正常候选池为空时进入兜底阶段

当正常候选池为空（分组、模型或请求约束导致无可用候选，或会话模式使正常候选不可用）时，系统 MUST 先尝试兜底渠道池，而不是直接返回无可用渠道。当兜底功能启用、但兜底渠道池为空或没有任何兜底渠道满足本次请求约束时，系统 MUST 保持既有失败语义，并记录一条 `fallback_exhausted` 决策事件，以便与「未配置兜底渠道池」区分；当兜底功能总开关关闭时 MUST NOT 记录该事件。

#### Scenario: 候选池为空但有兜底渠道

- **WHEN** 本次请求在正常候选池中没有任何可用渠道，且兜底渠道池中存在满足约束的渠道
- **THEN** 请求使用兜底渠道，不返回无可用渠道错误

#### Scenario: 候选池为空且无兜底渠道

- **WHEN** 本次请求在正常候选池中没有任何可用渠道，兜底功能已启用，且兜底渠道池为空或全部被跳过
- **THEN** 请求返回无可用渠道错误，与既有语义一致，并记录一条 `fallback_exhausted` 决策事件

#### Scenario: 总开关关闭时不记录兜底事件

- **WHEN** 兜底功能总开关关闭，且本次请求在正常候选池中没有任何可用渠道
- **THEN** 请求返回与既有实现一致的错误，且不记录任何兜底相关的决策事件
