# Proposal

## Why

「会话与重试」里的全局兜底总开关关闭时，兜底功能整体不生效（后端不再进入兜底阶段，已标记的渠道也不参与兜底），但渠道列表仍显示「兜底」列、渠道新增/编辑仍显示「兜底模型」开关。管理员会看到实际无效的入口，容易误判为标记丢失或功能未生效，也无法从界面判断兜底当前是否处于关闭状态。

## What Changes

- 渠道列表：全局兜底总开关关闭时不再渲染「兜底」列；总开关重新开启后恢复显示。
- 渠道新增/编辑对话框：全局总开关关闭时隐藏「路由策略」区域内的「兜底模型」开关；重新开启后恢复。
- 仅改变前端展示条件。渠道已有的 `channel_info.is_fallback` 存储值、渠道更新接口语义、后端兜底判定与决策事件行为均不变。
- 不新增「兜底是否启用」以外的配置项，也不改变总开关本身的位置与用法。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `channel-affinity`：在「兜底渠道池配置」需求中补充全局总开关关闭时前端不显示兜底入口（渠道列表兜底列、渠道新增/编辑的兜底模型开关）的验收场景。

## Impact

- 前端代码：渠道列表列定义、渠道列表页、渠道新增/编辑对话框，以及一个读取 `channel_affinity_setting.fallback_enabled` 的共享取值 hook；相关前端测试需覆盖总开关关闭与开启两种渲染结果。
- 后端代码：无改动。
- 数据与接口：无新增字段、无 schema 或迁移改动、无 API 变更；总开关关闭期间已标记渠道的 `is_fallback` 值原样保留。
- 兼容性：原先持久化在浏览器本地的渠道列可见性偏好仍按原有合并顺序生效，不因本次改动被清除。
