## ADDED Requirements

### Requirement: 上游报文面板的可见性

使用日志详情 MUST 新增「上游请求」与「上游响应」两个可折叠面板，且 MUST 仅对管理员渲染。非管理员视角 MUST NOT 渲染这两个面板或其入口。

#### Scenario: 管理员查看日志详情

- **WHEN** 管理员打开某条 relay 类使用日志的详情
- **THEN** 详情中出现「上游请求」与「上游响应」两个可折叠面板，默认收起

#### Scenario: 非管理员查看日志详情

- **WHEN** 非管理员打开使用日志详情
- **THEN** 详情中不出现报文相关面板或其入口

### Requirement: 面板内容与格式化

面板内容 MUST 取自该日志 `request_id` 关联的报文记录，并以 JSON 格式化（缩进重排、可读且可复制）方式展示。当该次请求为流式响应时，「上游响应」面板 MUST 展示完整 SSE 原文而非逐帧结构。

#### Scenario: 展开上游响应

- **WHEN** 管理员展开某条非流式日志的「上游响应」面板
- **THEN** 展示格式化的 JSON 文本，可读且可复制

#### Scenario: 展开流式日志的上游响应

- **WHEN** 管理员展开某条流式日志的「上游响应」面板
- **THEN** 展示该次响应拼接后的完整 SSE 原文

#### Scenario: 内容被截断

- **WHEN** 管理员展开的报文体已被大小上限截断
- **THEN** 面板明确提示该内容已被截断

### Requirement: 无报文时的空值处理

当该日志没有可展示的报文（采集开关关闭、该渠道不在采集范围、或报文已随日志清理）时，面板 MUST 显示明确的空占位，MUST NOT 报错、MUST NOT 呈现为空白面板。

#### Scenario: 采集功能关闭

- **WHEN** 报文采集开关处于关闭状态，管理员打开使用日志详情
- **THEN** 两个面板显示空占位信息，详情其余部分正常显示

#### Scenario: 报文已过期清理

- **WHEN** 日志仍存在但对应报文已被清理，管理员展开面板
- **THEN** 面板显示空占位信息，不产生运行时错误
