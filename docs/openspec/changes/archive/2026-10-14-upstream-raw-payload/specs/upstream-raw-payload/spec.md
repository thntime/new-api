## Purpose

定义真实上游报文的采集与保存行为：把网关实际发往上游的请求体、以及上游实际返回的响应体（含流式完整原文）按请求留存下来，供管理员事后核对参数改写、上游返回内容与错误现场。

## ADDED Requirements

### Requirement: 报文采集开关

系统 MUST 提供一个全局的报文采集开关，其默认值为关闭。

#### Scenario: 开关关闭

- **WHEN** 报文采集开关处于关闭状态
- **THEN** 系统不采集任何上游报文，也不写入报文记录

#### Scenario: 开关开启

- **WHEN** 管理员开启报文采集开关后发生一次上游请求
- **THEN** 系统为该请求留下对应的报文记录

### Requirement: 采集内容与采集边界

开启采集时，系统 MUST 保存该次请求实际发往上游的请求体原文，以及上游实际返回的响应体原文。系统 MUST NOT 保存请求头或响应头。

#### Scenario: 普通转发请求

- **WHEN** 采集开启时发生一次非流式的上游请求
- **THEN** 报文记录同时包含该次请求的上游请求体与上游响应体

#### Scenario: 不写入鉴权凭据

- **WHEN** 上游请求携带 `Authorization` 等鉴权头
- **THEN** 报文记录中不包含任何请求头或响应头内容

### Requirement: 流式响应的原文形态

对于流式响应，系统 MUST 保存拼接后的完整 SSE 原文，保留上游返回的原始行（包含 `data:`、`event:` 等原始前缀）。系统 MUST NOT 仅保存逐帧解析后的 JSON 结构。

#### Scenario: 流式请求

- **WHEN** 采集开启时发生一次流式上游请求
- **THEN** 报文记录中的上游响应为该次响应的完整 SSE 原文，逐帧可读，且包含被解析层剥离的原始前缀行

### Requirement: 采集范围的渠道豁免

系统 MUST NOT 因某些渠道不经过统一的上游发送出口而中断其请求；这些渠道可以没有报文记录。报表面板在该情况下 MUST 表现为无数据，而不是错误。

#### Scenario: 未覆盖渠道的请求

- **WHEN** 一次请求经由不经过统一上游出口的渠道完成
- **THEN** 该请求正常返回给客户端，且该请求没有报文记录

### Requirement: 采集不得影响请求转发

报文采集、序列化与写入过程中的任何失败 MUST NOT 影响请求的转发、计费与响应，MUST NOT 向客户端返回采集相关错误。

#### Scenario: 报文存储不可用

- **WHEN** 报文存储出现写入错误或超时
- **THEN** 客户端仍然收到与未开启采集时一致的正常响应

#### Scenario: 采集计算不改变上游报文

- **WHEN** 系统采集请求体或响应体原文
- **THEN** 发往上游的字节与返回给客户端的字节均与未开启采集时完全一致

### Requirement: 报文与消费日志的关联

每条报文记录 MUST 携带所属请求的 `request_id`，且系统 MUST 支持按该 `request_id` 取出该请求的报文。同一 `request_id` MUST 只保留一条可读取的记录；在不支持 upsert 的日志库（ClickHouse）上，这一保证通过「写入时追加、读取时取最新一次尝试」实现。

#### Scenario: 按 request_id 关联

- **WHEN** 以某条消费日志的 `request_id` 查询报文
- **THEN** 返回该次请求的上游请求体与响应体记录

#### Scenario: 重复写入同一 request_id

- **WHEN** 同一 `request_id` 的报文被再次写入
- **THEN** 按该 `request_id` 读取时只得到一条记录，且内容为最后一次写入的报文

### Requirement: 报文大小上限

系统 MUST 对单条上游请求体与响应体设置大小上限。超出上限的内容 MUST 被截断，且截断事实 MUST 在记录与展示中可识别。

#### Scenario: 超大响应体

- **WHEN** 某次上游响应体超过大小上限
- **THEN** 报文记录保存上限内的内容，并标记该响应体已被截断

### Requirement: 报文的保留与清理

报文记录 MUST 与消费日志采用同一保留策略：当消费日志因保留期或容量被清理时，对应报文记录 MUST 被一并删除。

#### Scenario: 清理过期日志

- **WHEN** 系统清理超过保留期的消费日志
- **THEN** 这些日志对应的报文记录同时被删除

### Requirement: 明文保存与管理员专用访问

报文 MUST 按原文保存，不做字段级脱敏。报文数据 MUST 只能由管理员访问，非管理员 MUST NOT 取得报文内容。

#### Scenario: 管理员读取报文

- **WHEN** 管理员查询某条请求的报文
- **THEN** 取得未经脱敏的请求体与响应体原文，包含 prompt 等业务内容

#### Scenario: 非管理员读取报文

- **WHEN** 非管理员尝试访问报文数据接口
- **THEN** 系统拒绝该访问且不返回任何报文内容
